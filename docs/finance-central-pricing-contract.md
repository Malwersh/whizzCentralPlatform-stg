تاريخ التنفيذ: 2026-10-15. الحالة: كود وواجهة واختبارات محلية، غير منشورة. المرجع [الخطة الموحدة](finance-pricing-settlements-returns-unified-plan.md) و[عقد المحرك الحسابي](finance-delivery-pricing-contract.md).

## الخدمة والحماية

أضيفت وحدة `backend/staff-service/delivery-pricing.js` داخل خدمة موظفي المنصة الحالية، وتوجيهها بعد مصادقة Cognito الحية والتحقق من حالة الموظف. لا توجد خدمة حساب مالي أخرى أو جدول معاملات جديد. تستخدم جدول StaffTable الحالي بقسم `OPERATIONAL_SETTINGS#DELIVERY_PRICING`:

| المسار | العمل | الإذن |
|---|---|---|
| GET /staff/pricing | المنشور والمسودة وصلاحيات الإجراءات | pricing.read |
| GET /staff/pricing/history | إصدارات منشورة، عشر نسخ للصفحة | pricing.read |
| POST /staff/pricing/draft | حفظ مجموعة قواعد كاملة كمسودة | pricing.request مع read |
| POST /staff/pricing/publish | اعتماد المسودة ونشر نسخة جديدة | pricing.approve مع read |
| POST /staff/pricing/simulate | حساب رسوم الزبون والأجرة من نسخة محفوظة | pricing.simulate مع read |

الأدوار الجديدة pricing_viewer وpricing_editor وpricing_approver مستقلة، وتتطلب نطاق جميع المناطق. دور المالية أو Merchants أو Settings لا يرث تعديل التسعير. تتبع bootstrap_admin آلية المستودع الموجودة لجمع الصلاحيات؛ لم تُسند أدوار أو تُعدّل سجلات أشخاص. تزامنت لقطتا أدوار Authorizer المحفظة مع الكتالوج دون إضافة عملية مالية أو تغيير التفويض الفعلي المنشور.

الحفظ والنشر يحتاجان MFA مكتملًا ومصادقة حديثة وفق `recent` الحالي. الحفظ يقبل baseVersion وdraftVersion وvalues وreason فقط. النشر يقبل الإصدارين والسبب دون السماح للمعتمد باستبدال القيم ضمن طلب الاعتماد. تمنع الخدمة اعتماد الشخص لمسودته حتى عند اجتماع الدورين، وتعيد قراءة صاحب المسودة والتحقق من صلاحية إعداده ونطاقه وحالته قبل النشر. آخر من يحفظ المسودة يصبح صاحب مقترحها؛ التدقيق يحتفظ بتاريخ التعديلات السابق.

## التخزين والإصدارات

- CURRENT: مجموعة القواعد المنشورة مع إصدار السياسة ومعدّها ومعتمدها ووقت النشر وسببه.
- DRAFT: نسخة كاملة بمخطط المحرك، وإصدار مسودة متزايد وإصدار المنشور الذي بنيت عليه. جميع أعلام القواعد فيها DRAFT؛ لا يقبل العميل إدخال PUBLISHED لتجاوز الاعتماد.
- VERSION#رقم: نسخة نشر غير قابلة للاستبدال، تحمل مجموعة القواعد كاملة. لا يحدث نسخ التاريخ عند كل ضغطة تحرير محلية؛ الحفظ والنشر كلاهما مدققان.

تجمع معاملة الحفظ حارس الموظف وشرط نسخة CURRENT وكتابة DRAFT بشرط نسختها وسجل التدقيق. تجمع معاملة النشر حارسي الموظفين وCURRENT المشروط وDRAFT المشروط وVERSION جديدًا والتدقيق. تزداد نسخة المسودة عند نشرها وتوسم publishedVersion، فلا يعاد نشرها نفسها. تعارض الإصدار أو فشل التدقيق/الحارس لا يعلن نجاحًا. المعاملات تختبر غياب السجل عند التهيئة؛ غياب الإعدادات عند القراءة لا يخلق سعرًا أو يكتب سياسة افتراضية.

يتحقق الخادم من بنية القواعد والمال والشرائح والتغطية والذروة، ومن تعارض فترتين بالنطاق والأولوية والمركبة؛ يرفض التعارض عند حفظ المجموعة قبل الوصول إلى التنفيذ. لا يسمح بتغيير محتوى قاعدة موجودة في CURRENT تحت id/version نفسيهما؛ يلزم الإصدار التالي عند تغييرها. هوية التتبع الكاملة تشمل إصدار السياسة أيضًا؛ ليست هذه خدمة استرجاع قواعد تاريخية منفردة حسب معرفها فقط. إزالة قاعدة من المسودة لا تمس المنشور حتى الاعتماد، وتبقى النسخ التاريخية محفوظة.

حجم مجموعة القواعد محدد بـ160 كيلوبايت، وحدود أعداد القواعد والشرائح والفترات من المحرك قائمة. مؤشر التاريخ لا يسمح بتغيير القسم أو بادئة VERSION. لا تنفذ هذه الدفعة سياسة احتفاظ أو حذف تلقائي لتاريخ التسعير أو سجل تدقيق المنصة.

## المحرك والمحاكاة

أضيف `validatePricingRules` إلى المحرك الحسابي المرجعي. سكربت `scripts/sync-delivery-pricing-runtime.cjs` يولد JavaScript للوحدتين Money وdeliveryPricing من TypeScript نفسه إلى `backend/staff-service/pricing-runtime` مع بصمة المصدر. فحص `--check` يفشل عند اختلاف النسخة، وربط الفحص قبل اختبار خدمة الموظفين وتغليف npm يمنع تغليف نسخة قديمة بهذه الآلية. يظل بناء TypeScript الكامل مطلوبًا؛ transpileModule وحده لا يثبت فحص الأنواع.

المحاكاة تختار DRAFT أو CURRENT المحفوظ وإصداره المتوقع، ولا تقبل قواعد أو أسعارًا حرة في جسم الطلب. تحويل أعلام DRAFT إلى PUBLISHED يحدث في الذاكرة للمحاكاة فقط، ولا يكتب في السياسة أو التدقيق أو ledger. تستعمل الدالتين الحسابيتين نفسيهما وتعيد تفاصيل النتائج ومرجع نسخة السياسة. الفترة والإحداثيات والمركبة لا تثبتها المحاكاة؛ مدخلاتها اختبارية من موظف مخول. لا تشمل هذه الشاشة توزيع فاتورة الطلب أو العمولة أو الإكرامية أو تمويل حملة أو أجرة عودة؛ تبقى تلك عناصر لاحقة للمحاكي الشامل.

مسار المحاكاة الحالي يسلم مسافات وأوقات مدخلة بوصفها ADMIN_SIMULATION إلى المحرك. وصف ROAD هنا فرضية سيناريو داخل محاكاة محمية، وليس إثباتًا لقراءة مزود طرق. الواجهة توضح هذا قبل الحساب ومع النتيجة. ربط الخرائط وحفظ عروض أسعار فعلية يحتاجان مسارات مستقلة تربط المصدر بالإحداثيات والفرع والزبون وتمنع حمولة العميل من ادعاء مصدر موثوق.

## الواجهة وإعادة استخدام الموجود

أضيفت `frontend/pages/delivery-pricing.html` وبرنامجها، وبداخلها Delivery Pricing وDriver Compensation وPricing Simulator وسجل الإصدارات. تدعم تحرير كل قيم العقد الحسابي، والشرائح ونوافذ الذروة، وتعرض تفاصيل القاعدة للمراجع دون الحاجة إلى فتح محررها، وتستخدم حقول اختيار التاريخ والوقت مع توضيح UTC. المبالغ تقرأ كنصوص عشرية وتتحول إلى أجزاء IQD بأعداد صحيحة دون parseFloat. زيادة إصدار القاعدة المنشورة إجراء صريح في المحرر.

أضيف مدخل Pricing & Commissions في sidebar ونسخته الاحتياطية مع تحقق صلاحية القراءة. بقيت الأقسام التشغيلية الحالية. أزيل نموذج Delivery Fees القديم من Financial واستبدل برابط للشاشة نفسها، وأوقفت قراءة قائمة قواعده القديمة في برنامج الصفحة؛ لا يوجد محرران فعالان للقواعد من الواجهة الجديدة. لم تُحذف مسارات local-dev-server التاريخية أو تعلن صالحة للاستخدام؛ مراجعة وإزالة بقية Financial والعمولات القديمة وإكمال هيكل المجموعات الأخرى من مراحل الخطة اللاحقة.

التحرير محلي حتى «حفظ المسودة»، وحفظها لا ينشرها. النشر يحتاج تأكيدًا للمسودة المحفوظة ولا ينشر تعديلات محلية غير محفوظة. تعارض الحفظ يبقي المدخلات المحلية ويطلب مراجعتها. المحاكاة ترفض العمل على تعديلات غير محفوظة، وتمسح النتيجة عند تغير مدخلاتها، وتهمل استجابة سبقتها تعديلات. إعادة تحميل فاشلة تخفي المحتوى السابق. النصوص والتاريخ تعرض عبر textContent دون HTML من القواعد أو الأسباب. واجهة القراءة تخفي التحرير والنشر وتبقي المحاكاة بحسب الإذن.

## التحقق وحدود النشر

نجح بناء TypeScript واختبارات المحفظة الـ185، واختبارات خدمة موظفي المنصة الـ119، منها 11 جديدة للخدمة المركزية. تشمل الإضافات فصل الأدوار والنطاق، MFA والحداثة، ذرية الحفظ والنشر وحراس الإصدار، منع الاعتماد الذاتي، سحب صلاحية صاحب المقترح وفشل المعاملة، منع تغيير قاعدة منشورة بالإصدار نفسه، المؤشر المعزول، ومحاكاة النسخة المحفوظة دون كتابة مالية. هذه اختبارات مع SDK محاكى وليست تجربة معاملات DynamoDB فعلية.

نجح اختبار Chrome المحاكى `scripts/test-delivery-pricing-browser.cjs` لإنشاء قاعدتي التوصيل والأجرة عبر النماذج وحفظهما ومحاكاتهما بالمحرك، وتعارض الحفظ والنص الآمن والقراءة فقط ومسح النتيجة القديمة. جميع طلبات المتصفح اعترضتها خدمة اختبار؛ لا كتابة AWS أو اتصال خرائط أو بيانات بشرية. اجتاز فحص تطابق المصدر والتغليف وفحوص صيغة JavaScript وفروق المسافات.

لم يتغير IAM أو Gateway أو Lambda أو Amplify فعليًا، ولم تحفظ سياسة أو أموال أو طلبات أو منح بشرية. قالب StaffTable المحلي يملك أذونات القراءة والكتابة والفحص الموجودة أصلًا؛ كفايتها الفعلية والتغليف والمسارات وCORS واختبار هويتين بشريتين تحتاج تحقق نشر. لم ينفذ طلب نشر التحويلات السابق المتوقف.

قبل التفعيل التشغيلي يلزم التحقق المرجعي من وجود معرفات الفروع والتجار والمناطق وعلاقاتها (تتحقق هذه الدفعة من صيغها فقط)، ومصدر خرائط خادمي، وQuote/Offer محفوظان مع TTL وبصمة المدخلات والإصدارات والقبول الذري، ثم ربط Checkout والإسناد والمحفظة والدفتر. نشر مجموعة قواعد هنا لا يجعل التطبيقات الحالية تستخدمها، ولا يعيد تسعير طلب مؤكد أو عرض مقبول تلقائيًا؛ لا توجد كتابة إلى تلك السجلات في الخدمة الجديدة.
