# حارس نطاق التجربة المنسقة — الجزء53

الحالة: تنفيذ محلي، غير منشور وغير مفعّل. [بيان البصمات والاختبارات](finance-rollout-scope-53.json). هذا استكمال لحارس النطاق ضمنT1 في [سجل الانتقال](finance-runtime-transition-51.md)، باستخدام الخدمات والجداول ومسارات التفويض الموجودة.

## النطاق الذي يطبقه الخادم

مصدر العقد هو `backend/wallet-service/src/financeRollout.ts`. يستعمل إعدادَي نشر `FINANCE_ROLLOUT_CONFIG` و`FINANCE_ROLLOUT_SHA256`؛ غيابهما أو اختلاف بصمتهما أو حساب/منطقة/بيئة غير Staging يمنع المسار الحديث. لا يفتح وجودهما علمًا تشغيليًا، ولا يحلّان محل Cognito أو العضوية أو صلاحية الموظف أو التحقق المالي.

يحصر كل نطاق معرّفات طلبات محددة، ويربط كل معرف بفرعه و`sub` العميل الموثق، ومعرّفات سجلات السائقين و`sub` المقابل لكل منها. لا يقبل بادئة معرف أو wildcard أو تسجيلًا ذاتيًا من جسم الطلب. حد التجهيز الحالي أربعة نطاقات، وفي كل منها عشرة طلبات وعشرة سائقين كحد أقصى؛ هذه حدود تجربة تقنية وليست تغييرًا لسياسة البحث أو أهلية السائقين العامة. إعداد الاختبارات تركيبي فقط؛ لم تُهيأ عينة بشرية أو تحفظ هذه الإعدادات في AWS.

للعينة التركيبية عبر API، يمكن تجهيز المعرف مسبقًا باستخدام `orderIdFor(userId, requestId)` المصدرة من محول إنشاء الطلب القائم؛ لا توجد خوارزمية معرف ثانية. يظل `requestId` بصيغة UUID وعقد تحقق الشخص والطلب كما كانا. مطابقة معرّف الطلب وحده غير كافية: الخادم يتحقق من هوية العميل والفرع المحفوظين أيضًا.

## السماح والتصريف

| الحالة | السلوك |
|---|---|
| `SCOPED` قبل `admitUntil` | يسمح باستقبال أعمال التجربة المحددة بعد التحقق الحالي من الهوية والمراجع والصلاحيات، وببدء موجاتها وعروضها المصرح بها |
| انتهاء مدة القبول أو `DRAIN` | يمنع إنشاء طلب أو موجة أو عرض جديد، ويحافظ على معالجة التسوية والعودة والإيصالات وإغلاق العروض للطلبات المقيدة بالنطاق المثبت |
| غياب الإعداد أو عدم مطابقته | لا تشغيل عام بديل؛ يفشل المسار الحديث مغلقًا |
| طلب عادي خارج العينة | يبقى على مسار التوافق القائم أثناء الانتقال، بعد أن يتحقق الكاتب من هويته؛ لا يُسقط Quote أو موافقة مالية لتشغيله عبر المسار القديم |

إغلاق مدة العينة لا يلغي طلبًا ولا يفك حجزًا. وضع التصريف يُطبّق وفق الإعداد الذي قرأه المضيف؛ تحديث متغيرات Lambda عبر الوظائف ليس إبطالًا ذريًا لحظيًا لاستدعاء بدأ بإعداد سابق. لذلك لا يُعرض هذا الإعداد بوصفه بديلًا لحواجز السحب والحذف والسياسة الحية، ويجب مطابقة إعدادات النشر قبل فتح العينة. أثناء التصريف تبقى بوابات إجراءات التسوية والعودة اللازمة متاحة وفق شروطها؛ إطفاء كل بوابات المالية سيمنع هذه الإجراءات أيضًا. لا يحول الحارس نهاية المؤقت إلى قرار مالي.

التوافق خارج العينة جزء من مرحلة الانتقال المحدودT6، ويُزال مساره المستبدل بعد قبول التحديث وتصريف الاعتماد التاريخي فيT7؛ ليس اختيارًا دائمًا لإبقاء محركين لإنشاء الطلب نفسه.

## تثبيت النطاق والمعاملة

تُحفظ `financeRollout` داخل الطلب من الخادم، وتحمل معرف النطاق وإصداره وبصمة عضويته. تستبعد البصمة وضع التصريف ووقت القبول، فتظل معالجة الطلبات الجارية ممكنة عند إغلاق القبول. تغيير الأعضاء أو السائقين داخل إصدار قائم يغيّر البصمة ويُرفض على الطلبات المثبتة سابقًا؛ تستعمل عينة جديدة إصدارًا مستقلًا، مع إبقاء الإصدار السابق أثناء التصريف.

الطلب الجديد يكتسب العلامة في Put إنشاء الطلب نفسه. طلب Legacy لا يكتسبها بسبب القراءة أو بسبب إيصال متأخر؛ تثبيتها الأولي مرتبط بمعاملة إنشاء مهمة الإسناد المثبتة الأولى. لا توجد تعبئة خلفية أو ترحيل تلقائي لطلبات جارية. الإرسال إلى الجهاز أو المزود يحتاج علامة محفوظة؛ قائمة الإعداد وحدها لا تكفي للإرسال.

يضيف ناقل DynamoDB المقيد فحص هوية الطلب وعميله وفرعه والسائق المعين وعلامة النطاق إلى معاملة التغيير القائمة. يدمجه مع عملية سجل الطلب الموجودة، أو يضيف فحصًا عند الحاجة، لتجنب عمليتين على العنصر نفسه. يرفض معاملة مالية لا يمكن ربطها بطلب، أو تجمع طلبين، أو محاولة كتابة إيصال أجنبي بعد التقاط استثناء قراءته. يظل شرط الحالة والتفويض والحذف والتمويل الأصلي قائمًا.

يصفّي مصدر المرشحين السائقين إلى عينة الطلب قبل الترشيح، مع إبقاء مؤشر المتابعة عند إفراغ الصفحة بالتصفية. يعاد فحص الزوج نفسه عند الكتابة وقبل الإرسال. يعالج العمال الطلبات بالتتابع؛ الفحص النهائي للمعاملة والإرسال مستقل عن تصفية المرشحين. لا يعلن هذا حل توسعة `LEGACY ALL` العامة خارج العينة أو رفع حدود قراءة الصفحات.

تستخدم بعض الوحدات نسختين من SDK؛ فُحص التصنيف بتجميع مصغّر فعلي. لا يعتمد الحارس اسم فئة قابلًا للتغيير أثناء التجميع؛ النسخ غير المعروفة تُرفض. هذا إثبات للنسخ المختبرة، ولا يفترض دعم SDK قديم غير مفحوص.

## المداخل والتجهيز المنسق

رُبط العقد بمصدر Quote وإنشاء الطلب، ومنشئ الإسناد وStartWave وعامل المهل والقبول والرفض والجسر في Drivers API، والخدمة المالية، ومستهلكَي الأحداث ومضيف القرار في COD integration، ومسار مراجعة الموظف، وناقل Push المثبت، وعامل إشعارات المحفظة. لا شاشات أو جداول جديدة لهذه الخطوة. صلاحيات المالك والموظف والسائق تظل مصادرها السابقة.

يفحص `scripts/check-finance-rollout-deployment.cjs` اتفاق إعدادات وظائف النطاق الثلاث عشرة وحسابها ومنطقتها وبصمتها. يرفض إزالة عضوية إصدار جارٍ أو إعادة فتح إصدار `DRAIN` عبر مساعد `preserveDrainingScopes`؛ إزالة النطاق بعد التصريف تحتاج فحصًا نهائيًا مستقلًا. نجاح هذا الفحص ليس تفويض تفعيل ولا إثبات مطابقة الحزم أو صلاحيات IAM أو خلو الحجوزات.

تُولّد نسخ CJS للمنصة وناقل Push وعامل الإشعارات من المصدر نفسه بواسطة `sync-finance-rollout-runtime.cjs`. وتستخدم خدمة المستخدم آلية توليد Quote الحالية. أُوقفت أداة مرشحي52 عند وجود العقد الجديد برسالة `TRANSITION52_SUPERSEDED_BY_SCOPED_RELEASE`؛ حزم52 القديمة لا تشمل جميع اعتماديات النطاق، ولا تُنشر فوق هذا الربط منفردة.

علامة النطاق داخلية؛ أزيلت من إسقاط ردود المستخدم والتاجر ومن غلاف ردود السائق. يلزم تضمين نسخ الإسقاط الجديدة في حزم القراء المنشورة أيضًا، وليس الكاتب وحده.

قبل تجربة Checkout على الأجهزة يلزم مواءمة معرف محاولة التأكيد الذي يولّده التطبيق مع معرفات العينة المعتمدة؛ لم يتغير مولد UUID في Flutter بهذه الخطوة. العينة الحالية مناسبة للتحقق المنسق عبر API بمعرّف محاولة معلوم، ولا يعني إنجاز الحارس أن نسخة التطبيق العامة أصبحت مهيأة تلقائيًا لهذه العينة. تبقى مواءمة العميل ضمن تجهيزT2وT5 قبل تجربة بشرية.

## التحقق وحدود التسليم

الاختبارات محلية، وتشمل النطاقات الأجنبية، وانتهاء القبول والتصريف، وعدم تغيير الإيصالات الأجنبية، وتثبيت العلامة ذريًا، وتبديل العضوية بين المضيفين، وتصفية المرشحين والمؤشر، وثبات نطاق السائق، ومنع fallback لطلب Quote، وإخفاء العلامة في الردود. بُنيت ست وحدات تشغيل من المصدر للتحقق من اعتمادياتها؛ ليست مرشحات ZIP من الحزم الحية أو إثبات نشر.

قبل تشغيل عينة Staging: يعاد تنزيل الحزم والإعدادات الحالية، وتراجع أذونات قراءة حقول هوية الطلب وعلامته وفحصها في المعاملات، وتُطابق نسخ الإسقاط، ثم تجهز حزم منسقة ببوابات مغلقة. يحتاج ناقلا الإشعارات خصوصًا قراءة هوية الطلب المحددة قبل الإرسال. لا يمنح هذا الجزء أذونات فعلية أو يعيد نشر مكدس كاملًا. يلي ذلك إعداد عينة محددة وفحص متطلبات التسعير والتمويل والهوية والمزود والأجهزة قبل التفعيل المحدود.

لم تُستدع خدمات AWS في هذا الجزء، ولم تُقرأ طلبات أو أرصدة بشرية أو تُرسل رسائل أو يتغير طلب أو مال. آخر لقطة منشورة سابقة تبقى تاريخية، وتُقرأ الحالة الحية مجددًا قبل النشر. لم تتغير واجهات Flutter أو موضع اختبار السائق أو مؤشراتv1.6 أو الإنقاذ الممول. اكتمال الحارس في المصدر لا يعني اكتمال تحققT1 المنشور أو مراحلT2–T7.
