# Staging driver editor

The old editor projected nonexistent regionName/regionNameArabic/regionCode fields, loaded regions twice and tried selecting a combined display address by text. It is now backed by paginated WizzCentral_Regions and WizzCentral_RegionsDerived_staging reads, merged by regionId. Governorate/work-area selects use saved IDs and valid parent hierarchy. Existing closed assigned regions may be retained; choosing a new closed region is blocked. Changing the work area while the driver is online is blocked to avoid a mismatch with live-state routing. Home/work region mirror fields are saved together, consistent with the current driver registration schema and routing implementation.

The modal resets before opening, disables save during loading, rejects stale asynchronous responses, and uses updatedAt as a concurrency condition on update. Ordinary edits preserve approval fields; explicit status changes update administrative status/verification together. No driver record is created by an editor update. Schema-v2 profiles hide obsolete numeric identity/license fields and preserve existing values. Landmark and vehicle selection are editable; car/motorcycle match current registration choices. Documents retain existing private signed-URL viewing.

Tests: three region model tests for hierarchy, activation, invalid assignments, supported vehicles, and online-area-change restrictions; existing central tests pass. Syntax checks passed. Published to Staging; signed-in modal/save acceptance remains with the administrator. No driver's actual data was changed during these tests.
